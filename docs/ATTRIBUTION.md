# Attribution and code comments

All work in scotf-org repositories is attributed to **TOTEM Agentic OS (TAO)**, https://url.totemltd.com/tao.
Never name an AI model, assistant or vendor in code, comments, commits, pull requests or generated files.

## Commit messages
Start with the issue key; end the subject line with the workstream tag in braces, one of `{platform}`, `{pilots}`, `{standards}`, `{guidance}`, `{control}`; end the message with the TAO trailer (one blank line before it):

    SCOT-17: add data flow figure {pilots}

    Built-with: TOTEM Agentic OS (TAO) <https://url.totemltd.com/tao>

## Pull requests
Title: `SCOT-n · name {workstream}`. Description ends with:

    Built with TOTEM Agentic OS (TAO) · https://url.totemltd.com/tao · {workstream}

## File headers (code and scripts)
Every source file (.mjs, .js, .ts, .py, .sh and similar) starts with:

    // <one line: what this file does>
    // Part of Freshness Reference, contributed by TOTEM LLC. Licensed under Apache-2.0.
    // Built with TOTEM Agentic OS (TAO) · https://url.totemltd.com/tao

Use the comment syntax of the language (`#` for Python, shell and YAML). JSON files cannot carry comments; put attribution in the schema `$comment` or `description` where the format allows.

## Comments in code
- Explain why, not what. Short, plain, specific.
- No narration of how the code was produced, no "generated by" lines, no model names.
